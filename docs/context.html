Independent Prolog contextual estimator

The estimator takes already formed SOP request candidates and context from the caller. It returns an ordering and the evidence behind it. The text reader can run independently, so the same candidate set can be inspected under different context snapshots. Ranking preserves alternate readings for the caller. It leaves object lookup and execution to downstream components. Prolog estimator · Node integration

For a targetless spatial pronoun such as “move it near the blue object,” the text reader keeps a leading unresolved-family interpretation and offers family hypotheses licensed by declared relation and anchor keys. Each hypothetical target is existing, has fill=context, and leaves the instance open for lookup. A tab or a selected live entity can favor one family.

Input and result

Provide a candidates array of objects with sop, plus an optional context object. Context can carry a tab, live entities, and past turns. Entities identify their family and can include an id, name, sort and selected flag. Pass turns in chronological order with text, sop or both.

The result includes selectedIndex, decision and ranking. Each ranking entry points to the input index and includes its score and reasons. In the combined reader, generatorIndex records that index after reordering. A candidate must contain a schema-valid request. invalidIndices lists excluded inputs. Scores order the hypotheses and their magnitude has no calibrated probability interpretation.

How evidence affects the ranking

  • Schema. The tab supplies positive evidence for matching target families and request keys and negative evidence for conflicting ones.
  • Live entities. The strongest compatible signal comes from an exact ID or name match, an unnamed target matching a selected entity, or a compatible sort. Explicit equality selectors can confirm or contradict the supplied live properties. Requested result values have no effect on this comparison. A target in new mode gets no live-entity evidence.
  • Prior turns. Accepted circuits provide stronger evidence through shared identity, sort or family. For a turn with text alone, whole-token mentions of candidate names and world vocabulary for compatible families provide weaker signals. An accepted SOP takes precedence within its turn. History signals decay with age.

Prolog adds the strongest live-entity signal and strongest history signal to the tab contribution and a small prior based on input order. This prevents a candidate from rising in the ranking merely by repeating a match. context_favors means the selected candidate has a higher context contribution than every competing candidate. underdetermined retains a selected candidate when context does not favor it over every competitor. The other decisions are single_candidate and unresolved.

Try the estimator

The standalone command reads a JSON object from stdin. Use --batch to submit one object per line. The combined reader also accepts --context FILE and a context object on each batch line. The --tab option provides the active tab for callers that only have that hint. Estimator CLI · Reader CLI

printf '%s\n' '{"text":"create an object","context":{"tab":"diagram"}}' |
  node bin/formalise.mjs --worlds-only --batch

In the local run, the diagram tab moved the node target from index 1 to first place. The ranked result still contained all three candidates, with context_favors and a schema_tab reason for the winner.

To try the same ranking independently, run the reader without context, put the winning result and alternatives in a candidates array in that order, and pair it with "context":{"tab":"diagram"}. Pass the resulting JSON to node bin/estimate.mjs < hypotheses.json. The reader’s --context file contains only the context object.

In a worlds-only run, move it near the blue object produced six readings. The generator kept the direct referent open. The diagram tab promoted a node hypothesis, while selecting a drawn entity promoted a drawing hypothesis. Both decisions remained underdetermined because several readings within the favored family still competed. The selected entity supplied ranking evidence without binding its ID into the circuit.

Use the estimator from Node.js

import { createEstimator } from './src/estimate.mjs';

const estimator = createEstimator();
try {
  const { ranking } = await estimator.estimate(candidates, { tab: 'diagram' });
  console.log(ranking);
} finally {
  await estimator.close();
}
