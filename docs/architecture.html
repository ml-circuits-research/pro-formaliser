From utterance to request graph

  1. Load knowledge. Node reads the pinned SOP snapshot and any runtime overlays. The resulting vocabulary supplies acts, targets, determiners, discourse cues and typed properties. World loader
  2. Learn from annotated rows. The optional model groups exact utterances and abstracts grounded substitutions into typed patterns. It also learns lexical and context statistics for candidate generation. Training code · Slot forms · Reader context model
  3. Prepare evidence. The reader tokenizes while preserving source positions. It indexes patterns by a literal anchor and length bounds, gathers SOP and learned lexical hits, and prepares alignments to examples or annotated clauses. Text inside quoted labels is masked for clause and negation detection. Text formaliser · Example transfer
  4. Rank candidate circuits. A persistent SWI-Prolog worker receives each prepared request over JSON Lines. Its score orders exact examples, typed templates, alignments and lexical assemblies in descending priority. Template variables bind source spans and enforce their lexical type. Learned word associations can score already grounded action hypotheses. Lexical assemblies join a compatible act, target and constraints, with residual evidence recorded as unread. Before the Prolog shortlist, a frame that separates the target from other arguments can favor a target in its grammatical scope. Linguistic frames and ledger Prolog reader · Property rules · Role attachment
  5. Validate and retain alternatives. Node checks generated SOP against the loaded request schema and available acts and checks copied evidence against the source. Prolog returns a shortlist of twelve plus representatives for competing families declared for the same target phrase. Node retains valid circuits with distinct semantic wire signatures in the generator’s candidates array. The pipeline can select a leading proposal. If the caller supplies discussion context, a separate SWI-Prolog estimator ranks those same circuits using schema, live entities and prior turns. Contextual estimator Schema validation · Grounding checks

Composition and request scope

The reader can read independent clauses and combine their request wires, remapping local references and validating the combined circuit. Composition keeps up to twelve combinations and retains distinct whole-text alternatives. A construction with one grounded creation verb and several clearly delimited objects can produce one request per object, each with its own modifiers. Quotation and list boundaries protect literal content. Ambiguous attachment, especially a noun that could be part of a spatial anchor, can still leave the list incomplete. Composition rules

Declared scope cues identify questions, polarity, and conditional boundaries. A fronted or trailing present-state condition can add a selector to an existing target when a singular reference points back to that target and its property and value resolve uniquely. A negative guard uses want=no, while the effect retains its own property and value. Different subjects, unsupported conditions and unresolved properties fall outside this construction. Scope analysis · Scalar guards

A postfix count cue followed by a question mark can introduce a count question when the complete preceding noun phrase is grounded. A declared universal cue immediately before an existing target can supply fill=all and retain the written quantifier evidence. The resulting candidate still relies on the surrounding reading for the action and its properties. Set and count rules

Evidence-preserving candidate readings

The reader can attach an adjacent cardinal or ordinal to a uniquely located target. An adjacent adjective can supply a catalog-licensed property when training independently supports the same family and interpretation. That property selects an existing target or constrains a new result according to target mode. An explicit naming cue can bind a written name on a new target through a declared literal role. Nominal numbers · Nominal modifiers · Explicit name attachment

Whole-body transfer indexes the unchanged request body after accounting for declared boundary politeness, interjections and terminal punctuation. It preserves interrogative intent, rejects examples that carry prior-turn evidence and checks that literal fields stay grounded. The audits track which meanings the reader recovers and where the world contract falls short. Whole-body transfer · Expressivity audit · Measured grades

Reading the pipeline result

FieldMeaning
sourceThe construction that produced the candidate. Common values include example, template, alignment, lexicon and sequence.
supportTraining frequency where supplied. A reading licensed by SOP worlds alone can have zero support.
statusmatched for a matched construction, partial for a lexical or incomplete reading, or unresolved with empty SOP and the original text kept as unread.
alternativesOther valid, distinct readings. candidateCount and multipleInterpretations summarize the set. When context is supplied, estimation explains its ordering.

Use the reader from Node.js

import { createReader } from './src/runtime.mjs';

const reader = createReader();
try {
  const result = await reader.formalise('create an object', { tab: 'drawing' });
  console.log(result.sop, result.alternatives);
} finally {
  await reader.close();
}

Pass a trained model to createReader(model, worlds) to enable examples and learned patterns. The CLI accepts --model FILE and defaults to .cache/model.json. With --batch, supply one JSON object per line with text and optional context and tab. Use createFormaliser(model, worlds) directly for the text-only stage. The default CLI prints its candidate set. Pass --pipeline for a selected circuit with alternatives. Reader API · Formalisation CLI

Argument roles, coordination and preservation

A multiword property after a noun can transfer when independent training utterances and different nouns support the same family, act, mode, source phrase and value. An explicit naming result can license the same written name in the next spatial request, including lowercase names. The later target remains a written selector for subsequent resolution. Property phrases · Names across clauses

Replacement and other declared argument frames can separate a written target name, a quoted payload and a typed property. A declared coordinate construction binds a pair of numeric values in order, while spatial requests can bind a relation and a separate landmark lookup through world-specific keys. A targetless spatial reference can expose compatible family hypotheses with unresolved entity lookup for the context estimator. Named arguments · Spatial grounding · World declarations

The reader learns preservation patterns from requests with a grounded target and an explicit preservation property. Compatible stative verb senses can extend an attested construction. A domain may declare a custom preservation key and restrict its values through its catalog. Current training and world knowledge leave some preservation phrases unresolved. Domain bindings

Native English frames also contribute before the Prolog candidate limit and during lexical ranking. The word ledger, grammatical arguments and semantic wire comparison address different questions. Language knowledge · Failure diagnosis
