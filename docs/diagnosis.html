Diagnose formalisation failures

A structural mismatch identifies a pair to inspect. The diagnosis records a reviewer’s claim about one specific feature, then tests that claim with a witness circuit and a controlled contrast. Unreviewed disagreements and proposals with insufficient evidence are counted as unknown. The review cases refer to committed WebMeet rows by source and record number. Review plan and probes · Independent semantic review

Evidence for each diagnosis

AttributionEvidence
MechanismA valid circuit represents the reviewed feature. Neither the stored candidates nor the replay produces it from the original utterance, and an explicit contrast produces it using the same model and knowledge. This is a scoped candidate-generation diagnosis.
Missing knowledgeChange only SOP declarations and check the relevant catalogue entry before and after. Verify that the same contrast yields the feature only with the new declaration. Report the original utterance separately because attachment or target inference can still fail.
Schema expressive limitSpecify the required typed distinction and review possible existing encodings. Check that the native schema rejects the exact missing slot on a closed type and accepts the same witness after adding that one declaration. This establishes a contract boundary for the reviewed representation. The row attribution still depends on whether that distinction is required.
Ambiguous contextSupply two plausible contextual snapshots to the same candidates. The selected interpretations differ as reviewed, while the utterance and candidate circuits stay fixed.
AnnotationIdentify a specific mismatch between the annotation and the utterance. Provide a structurally distinct accepted witness for the reviewed feature. It can preserve other uncertain material as unread.
UnknownThe row is unreviewed, the intent or evidence is insufficient, or the current reader no longer reproduces the specific failure.

Validation and catalogue scope

The native SOP engine checks type declarations, slots, enumerations and local references. The pinned WebMeet checker also checks that phrases occur in the source, apply within the owning request, and follow the dataset's rules for target families, constraint keys and closed value banks in the row's tab. It accepts explicit open_value=true where applicable. The benchmark's text-only reader receives the utterance alone. The checker uses the dataset tab after inference. The checker reports warnings separately for phenomena such as unread material.

The checker emits grouped violations with example rows. The diagnostic uses a distinct temporary filename for each witness and requests enough examples to map every violation back to the witness. Native validity and checker errors are preserved separately. A checker pass can establish conformance while leaving semantic adequacy open. Diagnostic runner · Native schema differential

The standalone reading checker can expose whole-token evidence ranges, quote-only predicates and argument role conflicts before a reviewer chooses a diagnosis. It preserves multiple occurrences and reports uncovered tokens separately from lexical or schema errors. Inspect linguistic evidence

Measured bucket-0 review

The native-frame text-only run had 1,915 rows and 1,374 structural disagreements. The diagnostic reproduced all six stored candidate lists. Six reviewed probes yielded one mechanism attribution, one missing-knowledge attribution, one ambiguous-context attribution, one annotation attribution, and two unresolved probes. The other 1,368 disagreements were unreviewed. This purposive review does not estimate the prevalence of each cause. All six submitted witness circuits passed the native validator and pinned checker.

  • “Move it to Friday” never produced the plausible meeting.day=Friday candidate. The explicit meeting-day contrast produced it with the same model and declarations.
  • A single alias for chart.colourBarLength exposed “colour bar length medium” in the lexical catalogue and repaired the contrast with an explicit chart target. The original metonymic request still lacked the property.
  • Two plausible live entities named Kickoff switched the winner between node and drawn object among the same eight candidates.
  • The “add a paargraph” annotation targets an existing block. The witness creates a new paragraph and leaves “Main Track 3” unresolved.
  • The native-frame run generated replacement text for the reviewed Letter request. The historical release candidate set omitted that feature, so the reviewed omission did not account for the current disagreement. For the other unresolved case, the closed constraint type lacked a typed antecedent link. A previous-value lookup was legal, and the utterance did not isolate its intended prior effect, so the case remained unknown.

Reproduce and extend

From the repository root, use a text-only benchmark with --details and the matching trained model. The diagnostic preserves stored candidates and reports whether the current reader reproduces them. If replaying on a later code revision, inspect that field before comparing results.

node eval/diagnose.mjs .cache/primary.jsonl --model .cache/model.json \
  > .cache/diagnosis-primary.json
node --test test/diagnose.test.mjs

Pass --cases path/to/plan.mjs to use another plan exporting a cases array. Follow the release plan for scope, witness and probe fields. When reviewing a schema boundary, include the one-slot extension, witness and alternative encodings checked against the pinned schema. Keep subjective judgments in the review rationale and observed outputs in the generated report. Benchmark reproduction · Example plan
