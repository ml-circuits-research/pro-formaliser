Design decisions and unresolved issues

First release

Commit 9596a53 introduced repo-local SWI-Prolog and Node tooling, a one-edit spelling checker and a learned English-to-SOP reader. It established a normalized-text holdout before measuring, so the exact same normalized utterance could never appear in both training and test. The first text-only run matched all semantic wires for 93 of 1,915 rows. Worker log · Measured baseline

Runtime knowledge and scoped grounding

Commit 73e150f added declarative runtime bindings, schema-aware substitution, request composition and copied-evidence checks. New world facts can supply vocabulary and typed constraints without retraining. Optional word pairs and protected terms improved spelling on the held-out injection benchmark. IssueImplemented response and remaining limitation
Ungrounded or wrong-scope transferAlign slots to source evidence, resolve their values by schema and check evidence within each request. Guards avoid applying lexical result constraints across negation or clause boundaries. Target attachment and selection-versus-mutation errors still occur.
Several explicit actionsSplit on supported sequence boundaries and validate the recomposed graph. The review still exposes lost counts and anchors in complex multi-step placements.
Vocabulary absent from trainingInterpret world bindings at runtime and reuse the resulting vocabulary for spelling. New relation or reasoning mechanisms still require reader logic.
Wrong family across tabsUse application tab as a ranking preference while keeping alternatives. The tab-aware benchmark reduced checker errors from 208 to 20 on the same held-out rows. Text-only evaluation exposes how often application context matters.
Wrong correction of rare wordsUse dictionary and world vocabulary, protected words and contextual ranking. The spelling audit still found harmful edits on legitimate or domain-specific expressions such as deco and hatless.

Independent contextual ranking and role attachment

The text formaliser and context estimator now run as separate stages. A schema tab preference can be weighed alongside compatible live entities and prior turns. The estimator reports the selected index, ranking and reasons while preserving valid alternatives. Lexical attachment uses supported action role markers and spatial relations from SOP facts. These cues help distinguish a direct target from an anchor and a selection constraint from a requested change. They do not supply an instance lookup result. Contextual estimator · Role attachment rules

A learned lexical association had supplied the sort roof for the pronoun it. Declared headless references now keep the thing unresolved while preserving the wording of a spatial relation and its anchor. A family-specific key requires a grounded family. On six targeted drawing examples the worlds-only reader produced the intended distinctions on all six. With the trained model, four won and two still lost to a learned template for a part. This is a diagnostic set selected during development. Role regressions

Structural validation and evidence checks leave semantic questions open. Pronoun resolution, source-to-target attachment and full preservation of modifiers are recurring problems in the independent review. Normalized-text holdouts measure variation within WebMeet. Template-grouped or independently collected evaluations would test broader generalisation. The experiment produces request circuits for subsequent interpretation and execution. WebMeet key validation

The first role-aware run identified 327 constraints that represented a spatial relation but omitted the application key. The SOP type checker accepted these wires. WebMeet requires an attribute on each constraint. The reader now grounds the relation and its landmark separately using the request key declarations and retains an unread phrase when the family or keys are unresolved. The landmark has its own lookup. Key resolution · Custom spatial bindings
