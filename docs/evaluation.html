Holdout and metrics

The benchmark reads committed WebMeet blobs from revision a85de79de826f983855aa2dafc6de7548978fbff and uses knowledge revision ba7cbcf2ab78b8b99d077e8958013d52618c6d04. It groups texts globally using Unicode NFKC, lowercase and collapsed whitespace. A SHA-256 bucket determines whether the whole group is held out. Reported counts are row-weighted, so multiple annotations of the same text can contribute multiple rows. Related templates and paraphrases can straddle partitions. Corpus input · Benchmark methodology and tables

  • Exact compares trimmed SOP with normalized line endings.
  • Full wires canonicalizes slot order and local references and compares all wires and evidence.
  • Semantic wires compares the complete graph after omitting filler, unread wires and selected evidence fields. It retains request order, act, mood, target and relevant constraints and links.
  • Act/mood checks the sequence of acts and moods. Micro-averaged wire F1 gives credit for partial structural agreement.
  • Checker errors count invalid emitted circuits under WebMeet family/key checks using the gold tab after inference. The text-only reader receives no gold tab. Warnings and unresolved outputs have separate counts.

Reports distinguish the selected circuit from matches found anywhere in the proposal set. Text-only generation and scoring with the actual tab are measured separately. Tests change live entities and prior turns while holding candidates fixed. The tab benchmark measures the actual tab signal on held-out rows. Formalisation results · Signature computation

The frame-matching ablation compares semantic matches and checker errors with the grammatical evidence enabled or disabled. The diagnosis workflow uses scoped, reviewed test cases to investigate why individual readings differ. Linguistic benchmark · Failure diagnosis

Independent adjudication

For a proposal-set grade, reviewers assess meaning and essential details against the request before considering exact SOP text. L3 requires a reasonable exact match after line-ending normalization and trimming. L4 covers another reasonable representation or interpretation. When no complete proposal is reasonable, the closest usable reading determines the error grade. Findings about annotation defects are recorded separately. A downstream selector is evaluated on its selected reading. Random-sample protocol and results

The random-sample reviewers inspected the reference along with the proposals. Earlier blind reviews used anonymized pairs sampled from model–reference disagreements and describe failure modes within those disagreements. These samples answer different questions. Spelling measurements

The spelling benchmark injects a deterministic deletion, insertion or substitution into an eligible word and counts restored words, wrong replacements and unchanged words. A separate challenge uses dictionary-valid corruptions. The audit also reviews edits on original requests. Spelling benchmark counts · Spelling benchmark runner · Spelling audit

Reproduce the experiments

Run the commands from the repository root on Ubuntu 24.04 with signed APT repositories including Universe, Bash, Git, curl and dpkg. The setup provides Node 22.23.2 and SWI-Prolog 9.0.4 in .cache/. Place a sibling webmeet-dataset checkout with the pinned revision available in Git. The benchmark writes defaults to .cache/model.json and .cache/benchmark.json. Alternate outputs keep the primary model available to the CLI. Setup script · Benchmark runner

tools/setup
export PATH="$PWD/.cache/node/bin:$PATH"
npm test
node tools/train-spelling.mjs
node eval/spelling.mjs --no-context
node eval/spelling.mjs --legacy-context
node eval/spelling.mjs --all-changes
node eval/benchmark.mjs --details .cache/primary.jsonl
node eval/benchmark.mjs --bucket 1 --model .cache/replication-model.json   --report .cache/replication.json --details .cache/replication.jsonl
node eval/benchmark.mjs --context tab --model .cache/tab-model.json --report .cache/tab.json
node eval/sample-disagreements.mjs .cache/replication.jsonl .cache/blind

Evaluate argument and word preservation

The benchmark reports kept, omitted and added annotation obligations for actions, target families and modes, target details, selectors and results. A constraint key, phase and value must agree within the same request position. These structural counts are sensitive to alternative encodings. They do not attribute an added wire to invented words. A separate ledger counts grounded, unread, uncovered, grammatical, filler and ambiguous source occurrences. The upstream checker also reports its own warning categories for gold and predictions.
