Linguistic frames and evidence

The reader can cite a grammatical construction for a request act, its predicate, and the source spans of its arguments. The proof comes from native w.lang.en.frame and w.lang.en.part declarations in the loaded SOP worlds. Prolog uses separated object spans while assembling lexical candidates and returns the proofs so the reader can check each retained interpretation. Frame compilation and support · Prolog matcher

What the matcher checks

The compiler reads ordered parts and builds lexical events for act-specific verbs, declared lead phrases, determiners and fixed words. It supports frames with one verb and at least one required role that takes words. Leads may precede the verb. Consecutive role spans require an obligatory lexical delimiter between them. Frames requiring other domain or grammatical prerequisites are outside this fragment.

Prolog works backward from the end of the token sequence. It indexes lexical events by kind and value and tracks viable suffixes at each token boundary. Each argument consumes a nonempty contiguous span. Optional lexical parts may be matched or skipped, and a proof consumes the complete prepared sequence. The matcher retains one deterministic proof per frame and emits token ranges for the predicate and named roles. The compiler can ignore terminal periods and exclamation marks and avoids applying this simple frame analysis across recognized coordination or negation boundaries. Quoted arguments remain available as text spans while their contents supply no lexical events.

Typed property assignments

A separate matcher uses native set frames that require attrs or number and declare the property, owner and value roles. For “set the seat of o1 to the bench,” the catalog identifies the seat property, a declared code prefix identifies the owner family, and Prolog verifies that all three roles occupy the written spans specified by the frame. The value reader accepts a native catalog value, a number, or written text admitted by the property. Catalog bindings · Span matching

A postnominal numeric assignment also requires a native modality cue, as in “the node should have 30 width.” Native property questions use the same catalog and owner bindings. The resulting request records the asked key and the wording that identifies it. A numeric question such as “how many bins does the chart have?” requires a numeric property. Native and overlay fixtures

Native qualitative frames can bind an existing owner and a property value without a written property label, as in “the link should be dashed.” The owner family limits the available property keys. Distinct lexical aliases can support separate proposals, and a qualitative scale word can use a catalog-declared scale binding. Qualitative assignments

Object scope before the candidate shortlist

A frame that captures two or more arguments can distinguish the direct object from its value or another argument. The role declarations identify which captures can provide target evidence. For a matching act and predicate span, Prolog gives a lexical candidate a score bonus when its target is inside all applicable object spans. The bonus affects which readings survive the bounded candidate list, which retains up to twelve distinct SOP texts. Absent or conflicting scopes supply no bonus. The frame scope leaves other candidates eligible and preserves the source priority of examples, templates and alignments. Lexical candidate search

Hard checks and ranking evidence

The native engine, request catalogue and literal evidence checks gate admitted candidates. A predicate whose only whole-token occurrences in its own request are inside quotations fails the literal evidence check. A quote can be the content of an edit while the predicate remains grounded outside it. Grounding checks · Quotation scope · Request catalogue

pro.reader.evidence_role connects a named grammatical role to a wire type and field, optionally within a constraint phase. The shipped declarations compare target name and sort_words with the thing role, and result-phase constraint value with the value role. An argument_role_conflict occurs when a declared literal appears only in another role's span. Repeated occurrences across roles leave that attribution open. A frame may also provide soft competing_frame_act evidence for a different act.

After the shortlist is returned, these linguistic signals reorder retained lexical fallback candidates. A conflict-free proof provides positive ranking evidence if it discriminates by licensing a unique act for the predicate or separating multiple argument roles. A conflict-free generic one-argument frame supplies no positive preference among already licensed readings of a polysemous predicate. The reader preserves candidates with soft conflicts and the precedence of higher-priority sources. Role correspondence declarations · Candidate ranking

Inspect a reading and its evidence ledger

node bin/formalise.mjs --worlds-only --evidence "create an object"

--evidence adds a ledger and a catalogue report to the selected interpretation. The ledger lists whole-token literal matches within each request's source range, preserving all matching occurrences. It reports missing required literal fields and assigns each text token one of grounded, unread, filler, ambiguous_occurrence, grammar, or uncovered. Its ranges use UTF-16 offsets with an exclusive end. With --spell, those offsets refer to the corrected utterance. Frame proofs use token indices internally.

bin/check-reading.mjs takes a JSON object with text and sop from stdin. It emits native schema validity, literal evidence validity, the ledger, catalogue issues, quotation conflicts, and frame support for the supplied circuit. Reading checker · Evidence ledger

Try a new verb and a two-role frame

Save the overlay as language.sop. The new act and verb feed the same frame compiler as the pinned world. The required two-token delimiter with tag separates the object from the label.

@demo.tag k.actions.act name=apply_tag about="put a reference label on an object" role=thing
@demo.verb k.actions.verb act=apply_tag text=tagstamp
@demo.frame w.lang.en.frame name=demo.apply_tag act=apply_tag set=acts priority=10 role=thing role=value
@demo.frame.1 w.lang.en.part frame=demo.apply_tag at=1 is=verb act=apply_tag
@demo.frame.2 w.lang.en.part frame=demo.apply_tag at=2 is=role role=thing takes=words
@demo.frame.3 w.lang.en.part frame=demo.apply_tag at=3 is=word word="with tag"
@demo.frame.4 w.lang.en.part frame=demo.apply_tag at=4 is=role role=value takes=words
SOP_WORLDS=./language.sop node bin/check-reading.mjs <<'JSON'
{
  "text": "tagstamp Gauge with tag Reference",
  "sop": "@r w.request.request act=apply_tag predicate=tagstamp\n@t w.request.target request=$r family=drawn mode=existing fill=written name=Gauge\n@c w.request.constraint request=$r on=attribute attribute=drawn.label value=Reference operator=eq phase=result"
}
JSON

The checked example passed schema, catalogue and literal checks. It returned frame demo.apply_tag with thing=Gauge, value=Reference, and no role conflicts. Removing with tag from the input eliminated the frame proof. Swapping name and value in the circuit kept the literal checks valid and reported two role conflicts. Supplying quote "tagstamp" Gauge with tag Reference produced predicate_inside_quotation and failed the literal evidence check.

How to evaluate the mechanism

Frame coverage, argument conflicts and the evidence ledger describe support for particular readings. Full semantic agreement compares the request graph, including acts, targets, values and links. Runtime speed depends on the measured end-to-end benchmark. Evaluate each independently so a change in frame-based search or ranking can be understood alongside semantic matches, checker results and inference time. Benchmark report · Blind language audit · Failure diagnosis

On the text-only primary holdout, 155 of 1,915 selected readings had a named frame proof. Of those, 78 matched all semantic wires. Separately, 32 selected readings carried at least one soft linguistic conflict. The matching-enabled and disabled runs each had 541 complete semantic matches. WebMeet checker errors were 216 and 222 respectively. The concurrent runs took 118.9 and 118.4 seconds for inference, so these timings do not isolate latency.

Compare the same pinned split with frame matching enabled and disabled. --language off disables frame support, the object-scope bonus in lexical search, and the subsequent preference among retained lexical candidates. Both runs keep the grounding and quotation checks.
