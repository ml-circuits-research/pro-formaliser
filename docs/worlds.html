Extend the reader with declarations

Place additional SOP facts in a file or directory and set SOP_WORLDS. On Linux the variable accepts colon-separated paths. The loader processes directory entries in sorted order, and later declarations with the same wire type and ID replace earlier declarations. Start a new CLI process after editing the overlay. For programmatic use, loadWorlds({paths}) builds an explicit snapshot for createReader(model, worlds). World loader

Map declarations to reader behavior

DeclarationBehavior
k.actions.act, verb aliases and core.wordIntroduce predicates and surface forms. Known words also enter the spelling vocabulary.
std.schema.kind and optional pro.reader.targetSupply target families and allowed acts. Explicit target bindings can specify family, sort, tab and target mode.
k.actions.role, verb value frames and w.lang.en.prepDescribe supported role markers and spatial relations. The lexical fallback uses these declarations to distinguish direct targets from nominal spatial anchors and to produce grounded selector or result constraints for supported attachments.
pro.reader.spatialMatches a family and tab to a class key for canonical spatial relations and a fill+span key for grounded anchor phrases.
w.request.key and declared valuesSupply typed properties within a target family. Key/value aliases can name a closed value. Explicit labels can also ground new decimal numbers or quoted spans for corresponding key types.
w.reader.en.binding, filter and featureSelect facts by type, filter them and project a spelling and canonical interpretation from fields or a wire ID. For equality constraints the projected value must resolve to a compatible key in the target family.

Try a new domain without retraining

Save the worked workbench overlay as workbench.sop. The overlay declares a calibrate act, a fluxometer target, and a finish property with an alias for the canonical value frosted. The guide also shows how to obtain those aliases from filtered facts of a new type and how to add number and span keys. Worked overlay and binding contract · Target and spatial binding schema

SOP_WORLDS=./workbench.sop node bin/formalise.mjs --worlds-only --json   "calibrate the fluxometer surface finish fine texture"
SOP_WORLDS=./workbench.sop node bin/spell.mjs --json "Calibrate the fluxometer"

For the request, inspect the act, target, key/value and source evidence. If a surface phrase still resolves to several keys or values in the selected family, the reader preserves it as unread. For spelling, the new domain word is recognized through the same overlay. The existing contracts cover these operations without a dataset model. A new semantic operation requires an interpreter.
