## OWNER RULE — propose all reusable knowledge and schema changes to the coordinator

Send every proposed addition/modification of reusable SOP knowledge, vocabulary, relations, language constructions or schemas through integration-review.responses.md. State the meaning, exact candidate declarations/paths, current canonical equivalent or gap, consumer need and independent controls. The coordinator reviews the proposal, assigns canonical integration to the data/schema worker, independently validates and publishes it, and returns the canonical revision. Then update the installed pin, prove reader behavior against the canonical declarations and remove superseded local copies. This is not a second permanent knowledge catalog inside pro-formaliser.

Autonomous implementation/commits remain allowed for reader mechanisms. A pro.reader namespace does not by itself prove a declaration is implementation-only; reusable language/domain semantics still require canonical routing. Existing sop-worlds proposals must receive an explicit disposition: canonical integration with retirement, an explained implementation/test-only location, or rejection/removal after preserving valid behavior. Do not delete active concurrent work or remove a local proposal before its approved replacement is available. Submit new schema needs to the coordinator rather than installing an independent persistent schema silently.
